Task4 device-lifetime acceptance details:

- Stable per-unit identity is independent of a receiver path/slot. Every mutating request carries the expected identity and freshly verifies hardware unit bytes before the setter; cached Solaar IDs alone are insufficient after hotplug. - A private atomic/fsynced per-unit reporting journal and lifetime nonblocking lock preserve original flags/mappings. Persist original state and touched ownership before setters. On restart recover a prior journal before acquiring a new baseline; compare fresh identity and owned bits, preserve unrelated bits/mappings, fail closed on corruption/conflict/lock. Clear journal only after live confirmation. `stopped.restored` is true/false/null; unexpected child exits mean unknown, never inferred success.
- Remembered settings are explicit opt-in per stable unit, strictly validated against fresh descriptors before any replay writes. Commands and host switching are excluded. Explicit confirmed user changes may update desired state; read-only scans/battery/replay must not overwrite it. Work is serialized off GTK, cancellation and partial application counts are reported. - Integration requested intent is separate from running status. Bounded same-unit reconnect backoff is1,2,5,10,20,30seconds; opt-in only, manual Stop/Quit cancels it, and uncertain restoration blocks automatic restart. No overlapping workers. Native remapping, a hardware profile batch and host-switch requests pause and await confirmed restoration before mutation; a configuration lock prevents another listener acquiring ownership during the batch.
- Read-only Easy-Switch discovery uses verified GETs only; `get_host_names` and ChangeHost templates can write and are excluded. Switching is one explicit request after a fresh known paired channel, matching identity and clean reporting ownership; no automatic switch/retry and no real host-switch test.
